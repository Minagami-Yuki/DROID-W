## Dual Depth-Source Export Smoke Test

Goal: compare the two lightweight point-cloud export sources without rerunning SLAM.

Code changes:

- `src/utils/point_cloud_export.py` supports `point_cloud.depth_source: both` and `point_cloud.depth_sources`.
- `scripts_eval/export_point_cloud_from_video.py` exports point clouds directly from an existing `video.npz`.
- `configs/droid_w.yaml` now defaults to `point_cloud.depth_source: both`, producing `final_point_cloud_droid.ply` and `final_point_cloud_mono.ply`.

Input:

```text
/data1/czy/Output/DROID-omega/7Scenes/chess_seq01_omega_patch_token_uncertainty_v11_evidence_floor020/video.npz
```

Command:

```bash
conda run -n droid-w python scripts_eval/export_point_cloud_from_video.py \
  --video /data1/czy/Output/DROID-omega/7Scenes/chess_seq01_omega_patch_token_uncertainty_v11_evidence_floor020/video.npz \
  --output-dir /data1/czy/Output/DROID-omega/7Scenes/chess_seq01_omega_patch_token_uncertainty_v11_evidence_floor020/point_cloud_compare \
  --filename final_point_cloud.ply \
  --depth-source both \
  --stride 4 \
  --max-points-per-frame 12000 \
  --min-depth 0.05 \
  --max-depth 20.0
```

Outputs:

| Source | File | Points | Size |
| --- | --- | ---: | ---: |
| DROID optimized disparity | `/data1/czy/Output/DROID-omega/7Scenes/chess_seq01_omega_patch_token_uncertainty_v11_evidence_floor020/point_cloud_compare/final_point_cloud_droid.ply` | 1,439,509 | 21M |
| Mono / metric prior disparity | `/data1/czy/Output/DROID-omega/7Scenes/chess_seq01_omega_patch_token_uncertainty_v11_evidence_floor020/point_cloud_compare/final_point_cloud_mono.ply` | 1,440,000 | 21M |

Coordinate statistics:

| Source | Min XYZ | Max XYZ | P01 XYZ | P99 XYZ |
| --- | --- | --- | --- | --- |
| DROID | `[-20.45, -44.97, -93.82]` | `[150.77, 97.59, 111.52]` | `[-1.15, -4.35, -11.78]` | `[20.80, 13.89, 13.38]` |
| Mono | `[-2.91, -7.20, -61.79]` | `[62.34, 22.02, 20.35]` | `[-1.10, -3.70, -9.80]` | `[17.31, 11.92, 13.08]` |

Takeaway:

- The raw DROID-disparity export has much larger coordinate outliers than the mono/metric export.
- `video.npz` does not store `valid_depth_mask`, so this standalone script intentionally compares raw saved disparity sources. Full SLAM-time export can still use `valid_depth_mask` for the DROID branch.
- For visualization-quality point clouds, the next step should add uncertainty filtering, percentile depth clipping, voxel downsampling, and statistical outlier removal. The original DROID-W map-quality output is still the Gaussian map path (`final_gs.ply`) when `mapping.enable: True`.

## DROID-W Native Gaussian Mapping Smoke Test

Date: 2026-07-08

Goal: switch the main map output back to the original DROID-W/WildGS-SLAM mapping path instead of the lightweight raw point-cloud exporter.

Code/config changes:

- `configs/droid_w.yaml`: `point_cloud.save_final` is now `False` by default, so tracking-only runs no longer save misleading raw `final_point_cloud*.ply` files.
- `configs/Static/7Scenes/chess_seq01_droidw_mapping_smoke.yaml`: enables DROID-W native Gaussian mapping for a 120-frame smoke test.

Config:

```text
configs/Static/7Scenes/chess_seq01_droidw_mapping_smoke.yaml
```

Command:

```bash
conda run -n droid-w python run.py --config configs/Static/7Scenes/chess_seq01_droidw_mapping_smoke.yaml
```

Output check:

- `final_gs.ply` exists and has a Gaussian PLY header with fields `x/y/z`, normals, SH/color features, opacity, scale, and rotation.
- No `final_point_cloud*.ply` was produced in this run, as expected.

Takeaway:

- The DROID-W-native map-quality output is `final_gs.ply`, generated by the Gaussian mapper through `GaussianModel.extend_from_pcd_seq(...)` and subsequent RGB-D/uncertainty-aware optimization.
- The lightweight point-cloud exporter remains available for debugging through `scripts_eval/export_point_cloud_from_video.py`, but it is disabled by default and should not be treated as the DROID-W map output.

## MeshLab-Friendly Gaussian RGB Export

Date: 2026-07-08

Problem:

- `final_gs.ply` has accurate geometry, but MeshLab opens it without visible colors because native 3DGS stores color in SH/DC fields such as `f_dc_0`, `f_dc_1`, and `f_dc_2`, not in standard `red/green/blue` fields.

Code changes:

- `thirdparty/gaussian_splatting/scene/gaussian_model.py`: adds `GaussianModel.save_rgb_ply(path)`.
- `src/slam.py`: after saving native `final_gs.ply`, also saves `final_gs_rgb.ply`.

The RGB file keeps Gaussian centers as points and converts DC color coefficients back with:

```text
rgb = clamp(SH2RGB(features_dc), 0, 1)
```

Smoke conversion output:

| File | Purpose | Vertices | Size | MeshLab color fields |
| --- | --- | ---: | ---: | --- |
| `/data1/czy/Output/DROID-omega/7Scenes/chess_seq01_droidw_mapping_smoke/final_gs.ply` | Native 3DGS/DROID-W Gaussian map | 190,143 | 13M | `f_dc_*` |
| `/data1/czy/Output/DROID-omega/7Scenes/chess_seq01_droidw_mapping_smoke/final_gs_rgb.ply` | MeshLab-friendly colored point view | 190,143 | 2.8M | `red/green/blue` |

Color statistics for `final_gs_rgb.ply`:

| Channel | Min | Max | Mean |
| --- | ---: | ---: | ---: |
| R | 0 | 255 | 136.23 |
| G | 0 | 255 | 118.98 |
| B | 0 | 255 | 119.82 |

Takeaway:

- Use `final_gs.ply` for Gaussian rendering or downstream 3DGS processing.
- Use `final_gs_rgb.ply` for MeshLab/Open3D-style point-cloud inspection.
